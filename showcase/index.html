Diagram language trials

Two open questions for the house style. First: do the old category badges still earn their place now that card colour carries the tier? Second: can we animate, and should we? Scroll to the bottom for the motion test.

What I'd actually recommend

Process diagram — yes. B is the stronger diagram, and not because it's busier. The CODE pairing links Package Registry and Remote MCP Server, which the current version leaves looking unrelated even though they're the two halves of the same idea. That's the article's opening claim made visible.

Ecosystem diagram — probably not. Four of its five nodes would be META. A category that nearly everything shares isn't a category, it's noise.

Codex loop — no. The top-left corner is already taken by the numbered step chips, and those chips already carry the actor colour. A second chip beside them is clutter, and the diagram is sequential rather than categorical anyway.

One thing to decide either way: badges only work if the cards go quiet, as in B. Keeping colour-by-tier and adding badges means two encodings competing on one node — that's what made the very first WebMCP attempt feel muddy.

On the animation, honestly

Verify before you commit. The part I can't confirm from here is whether GitHub's sanitiser preserves an embedded <style> block on the gist raw-URL path. C uses SMIL and CSS deliberately so it doubles as the test: if the dashes stop marching but the packets still fly, <style> was stripped and CSS is out. Worth one throwaway gist before this goes into the house style.

SMIL is the safer bet of the two if only one survives — it's inline attributes rather than a style block, so there's less for a sanitiser to object to. The counter-argument is that SMIL has had a wobbly standards history (Chrome announced intent to deprecate years back, then reversed). Neither is risk-free; CSS is the more future-proof language, SMIL the more likely to survive sanitisation.

The accessibility gap is real. The CSS half honours prefers-reduced-motion — I've guarded it in C. The SMIL half cannot be disabled that way, so a reader with motion sensitivity gets the packets regardless. If that matters, it's an argument for keeping motion to the dashes.

And the editorial question. Motion suits diagrams about flow over time — a queue draining, a retry loop, packets racing down uneven branches. It actively hurts a structural diagram: the MCP ecosystem map isn't a thing that moves, and animating it would imply a liveness that isn't there. I'd keep motion for the loop-shaped diagrams and leave the architecture maps still.
